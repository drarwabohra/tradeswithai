# Integration and operations

This is a proposed replacement bundle, not a deployed application. Merge these files into the real repository, preserving unrelated files and media. The text export omitted ProductCard, format utilities, the product listing, legal pages, resources, and assets. The added listing/contact components replace or fill those paths; compare any originals first.

1. Install the new database dependency: `npm install pg server-only` and `npm install -D @types/pg`. Keep the existing Next 16.3.8, React, Tailwind v4, qrcode.react, and lucide dependencies. Commit the newly generated package-lock; do not hand-edit it.
2. Provision PostgreSQL and apply `migrations/001_orders.sql` once using the provider's SQL console or `psql "$DATABASE_URL" -f migrations/001_orders.sql`. This SQL is an initial migration, not a migration to rerun blindly.
3. Fill `.env.local` from `.env.example`. Set APP_ORIGIN to the exact public HTTPS origin in production. Configure actual site.json UPI ID and payee name. Verify them against the bank account in a small payment test. The supplied placeholder ID must never accept customer payments. Bank details are unused by this UPI-only checkout; remove the dummy bankDetails object or implement a separately validated bank-transfer flow before advertising that option.
4. Schedule an authenticated GET to `/api/order-outbox` every minute with `Authorization: Bearer <CRON_SECRET>`. Use your existing hosting scheduler. Do not expose this secret in browser code or URLs. The worker handles three deliveries per invocation; increase scheduling throughput deliberately if order volume needs it.
5. The receiver must validate X-TWA-Signature as HMAC-SHA256 over the exact raw `${timestamp}.${body}` using ORDER_WEBHOOK_SECRET, check timestamp freshness, and use orderId/Idempotency-Key to deduplicate. It must return 2xx only after durable acceptance. Delivery is at least once; a worker crash can cause retries. An HTTP 2xx alone is not proof that a notification email or spreadsheet row exists.
6. Monitor `SELECT * FROM twa_outbox WHERE failed_at IS NOT NULL` and jobs overdue by more than 10 minutes. Notify the operator using an existing monitoring system. After resolving a delivery failure, replay with `UPDATE twa_outbox SET failed_at=NULL,attempts=0,next_attempt_at=now(),locked_until=NULL,lock_id=NULL WHERE order_id='<ID>' AND delivered_at IS NULL`. Do not mark a bank payment verified just because an outbox job delivered.
7. The database is the order ledger. Back it up and restrict access to the operator. Choose and enforce a documented retention policy for abandoned orders and customer contact details; this patch intentionally does not delete paid-order evidence. The worker expires old rate-limit rows.
8. Keep /terms, /privacy, and /refund-policy as real, reviewed pages before accepting payments. Their text was absent. Do not ship placeholder policies, fabricate license terms, or imply source-code delivery grants unrestricted ownership. Set POLICY_VERSION when published acknowledgment/policy text changes. The new checkout records the version and timestamp, not a claim of legal sufficiency.
9. Verify each product's actual capabilities, versions, data source, data delay, data fees, license scope, and support scope. The bundle preserves supplied feature assertions where possible; it cannot validate trading-tool behavior from storefront code. Include these specifics next to requirements once confirmed. No fake testimonials, returns, or win rates.
10. Videos have no supplied caption/transcript assets. Create accurate demo transcripts and, for speech, WebVTT captions, then add `<track kind="captions" src="..." srcLang="en" label="English" />` and a visible transcript link. Do not add a broken track or invent spoken content. Purely silent videos still need an equivalent written description of the steps demonstrated.

## Required checks in the real repository

Run `npm run lint`, `npx tsc --noEmit`, and `npm run build` after dependency installation and actual payment configuration. Inspect at 320, 375, 390, 768, 1024, and 1440 CSS pixels; keyboard-only; reduced motion; 200% zoom; enlarged text; and actual iOS/Android UPI handoff. Check footer focus targets against the measured buy bar. The 44/48 px targets are design choices; they are not a blanket statement about all accessibility standards.

Use a staging database and stub webhook to test: malformed JSON; array bodies; >8 KiB; invalid/unknown product; email/name/phone boundary cases; UTR with spaces; UTR containing letters; 11/13 digits; consent false; forged token; repeat identical submission; concurrent submissions; duplicate UTR; create response lost then retried; transaction commit response lost then retried; database unavailable; webhook 502/timeout; outbox lease expiry; receiver duplicate delivery; worker dead-letter monitoring. Confirm bank payment stays PENDING_VERIFICATION throughout. Never infer payment from UTR syntax.

New order IDs are full server UUIDs, removing short client-generated IDs and arbitrary URL overrides. No URL order parameter is trusted. Browser Back returns to the product/previous page, because this replacement deliberately uses an explicit Edit button instead of brittle custom history entries. If native Back must traverse checkout steps, implement and test a routed step flow; do not restore success from history/localStorage.

Session recovery stores contact details and an unpredictable request ID only in sessionStorage, not order credentials or success state. It survives reload in the same tab. Storage failure is caught and communicated. Once a receipt is shown, the browser copy is cleared; users are asked to retain the durable server-issued order ID. Lost-tab recovery uses support rather than an unauthenticated endpoint exposing PII. A future order-status feature needs authenticated or securely signed access.

Rate limits are durable but modest. Set TRUSTED_CLIENT_IP_HEADER only with deployment documentation proving that the edge overwrites it. The shared fallback protects storage volume but can affect buyers together. Configure deployment-level body limits and request timeouts too: the 8 KiB streaming parser bounds application bytes, not slow-client connection duration. The Origin check deters browser-origin misuse; it does not authenticate public API callers or stop curl. The per-order token authorizes receipt changes. For meaningful abuse volume, add a managed edge limiter/challenge rather than relying on unbounded in-memory Maps.

No backend can undo or prove a manual bank transfer from a browser. The UI therefore says when a request was recorded, distinguishes verification from delivery, and gives a retry/support path without asking the buyer to pay twice.
